Evaluation results¶

Reads what evaluate.py wrote to results/ (<tag>_metrics.json and <tag>_preds.jsonl per run) and compares the runs: output validity, per-field accuracy, per-example errors, and labels the model invented. Every chart has a table with the exact numbers next to it; with n=12 test rows, one row is about 8 percentage points.

schema = load_schema()
allowed = {"primary_category": set(schema["primary_category"]),
           "specific_issue": {i for issues in schema["specific_issue"].values() for i in issues},
           **{f: set(schema[f]) for f in ("situation", "suggested_action", "urgency")}}


def is_invented(field, value):
    """A predicted value that isn't an allowed label anywhere in the schema (missing values are NaN)."""
    return isinstance(value, str) and value not in allowed[field]


metrics, rows = {}, []
for p in RESULTS_DIR.glob("*_metrics.json"):
    tag = p.name.removesuffix("_metrics.json")
    metrics[tag] = json.loads(p.read_text(encoding="utf-8"))
    for r in load_jsonl(RESULTS_DIR / f"{tag}_preds.jsonl"):
        pred = r["pred"] or {}
        row = {"run": tag, "id": r["id"], "complaint": r["complaint"], "raw_output": r["raw_output"],
               "parsed": r["pred"] is not None, "schema_valid": schema_valid(r["pred"], schema)}
        for f in FIELDS:
            row[f"gold_{f}"], row[f"pred_{f}"] = r["gold"][f], pred.get(f)
        rows.append(row)

# Fixed run order (zero-shot, few-shot, then fine-tuned adapters) and a fixed color per run
runs = sorted(metrics, key=lambda t: (MODE_ORDER.index(metrics[t]["mode"]), t))
COLORS = {t: PALETTE[i] for i, t in enumerate(runs)}
preds = pd.DataFrame(rows)
preds["run"] = pd.Categorical(preds["run"], categories=runs, ordered=True)
preds = preds.sort_values(["run", "id"]).reset_index(drop=True)
n = metrics[runs[0]]["n"]
print(f"{len(runs)} runs, {n} test rows each: {runs}")

========================= base_fewshot =========================
Classify a hearing aid patient's complaint into a one-line JSON object with exactly these keys: primary_category, specific_issue, situation, suggested_action, urgency. Use only the allowed values below.

primary_category (the single problem the patient emphasizes most):
  - sound_quality: How sound itself is perceived (loudness, tone, feedback, distortion, own voice).
  - speech_understanding: Difficulty understanding speech in a given setting.
  - connectivity: Bluetooth, phone app, and streaming or accessory problems.
  - discomfort: Physical comfort and fit in or on the ear.
  - battery_charging: Battery life, charging, and charger problems.
  - performance_practicality: Whether the device works, and day-to-day handling, cleaning, and appearance.
  - other: Positive feedback, cost or service, unrelated questions, vague messages, and medical red flags.

specific_issue (must belong to the chosen primary_category):
  [sound_quality]
  - too_loud: Sounds or overall volume uncomfortably loud.
  - too_soft: Sounds too quiet; patient can barely hear. No description of a dead or failing device.
  - tinny_or_harsh: Thin, sharp, high-pitched, or metallic tone.
  - muffled_or_boomy: Dull, underwater, or bass-heavy tone.
  - own_voice_issue: Patient's own voice sounds boomy, echoey, or odd.
  - feedback_whistling: Whistling or squealing.
  - distortion_or_static: Crackling, buzzing, static, or garbled sound.
  - background_noise_annoying: Ambient noise itself is bothersome or overwhelming. The complaint is the noise, not understanding people.
  - other_sound_quality: Sound quality complaint that fits none of the above.
  [speech_understanding]
  - speech_in_noise: Hard to understand people when there is background noise.
  - speech_in_quiet: Hard to understand people in quiet settings.
  - phone_calls: Hard to understand on calls. Not a dropout or connection problem.
  - tv_or_media: Hard to understand speech on TV, movies, or other media.
  - soft_or_distant_voices: Hard to hear quiet or far-away talkers.
  - other_speech: Speech understanding complaint that fits none of the above.
  [connectivity]
  - bluetooth_dropout: Connection to phone cuts out or is unstable.
  - pairing_failure: Cannot pair or re-pair with a device.
  - app_issue: Companion app crashes, shows wrong information, or controls do not respond.
  - streaming_audio_quality: Streamed audio is too quiet, distant, or poor compared with normal hearing.
  - other_connectivity: Other accessory or streamer problem (TV streamer, remote microphone).
  [discomfort]
  - pain_or_pressure: Pain, soreness, or pressure while wearing the device.
  - skin_irritation: Itching, redness, or irritated skin.
  - loose_or_unstable_fit: Device slips or falls out.
  - ear_fullness: Generic plugged or full feeling in the ear. Not specifically about own voice.
  - other_discomfort: Discomfort that fits none of the above.
  [battery_charging]
  - short_battery_life: Battery runs out sooner than expected.
  - charging_failure: Device will not charge or charger shows an error.
  - charger_issue: Seating, case, or charging-routine problem. Device itself may be fine.
  - unexpected_shutdown: Device turns off while the indicator still shows charge.
  - other_battery: Battery or charging issue that fits none of the above.
  [performance_practicality]
  - device_not_working: Device is dead, silent, or intermittently powering on.
  - moisture_or_wax_damage: Problem attributed to moisture, sweat, or wax.
  - handling_difficulty: Hard to insert, remove, or operate (dexterity, small parts).
  - cleaning_maintenance: Questions or problems about cleaning, wax guards, or upkeep.
  - cosmetic_or_size: Visibility, bulk, or appearance.
  - other_practicality: Practical issue that fits none of the above.
  [other]
  - positive_feedback_no_issue: Positive message, no problem to solve.
  - cost_or_service: Pricing, billing, appointment access, or warranty.
  - unrelated_to_device: General hearing question or non-sudden tinnitus question. No red-flag symptoms.
  - sudden_hearing_change: Abrupt change in hearing over the last days, especially in one ear. Red flag.
  - unclear_or_insufficient_info: Too vague to assign a problem.

situation (setting stated or clearly implied):
  - quiet_home: Quiet indoor setting at home.
  - noisy_restaurant_or_group: Restaurant, party, or group conversation.
  - phone_call: During a phone call.
  - tv_or_media: TV, movies, music, or streamed media.
  - own_voice: While the patient is speaking.
  - outdoors_or_weather: Outdoors, wind, rain.
  - car_or_transit: In a car or on public transit.
  - exercise_or_activity: Exercise, chewing, or physical activity.
  - work_meeting_or_lecture: Meeting, classroom, or lecture.
  - all_the_time: Persistent regardless of setting.
  - not_stated: Text does not indicate a setting.

suggested_action (most likely first clinic step):
  - adjust_programming: Fix likely through fitting software: gain, noise management, feedback manager, streaming balance.
  - physical_fit_adjustment: Fix likely through dome, earmold, tubing, vent, or seating change.
  - check_hardware_or_repair: Device inspection, cleaning, repair, or replacement.
  - troubleshoot_connectivity: Re-pairing, phone or app settings, updates.
  - user_education_or_counseling: Usage habits, handling, expectations, or non-urgent questions.
  - administrative_followup: Billing, scheduling, or warranty.
  - request_more_information: Message too vague to act on.
  - escalate_medical: Red flag. Needs clinician or medical evaluation.
  - no_action: Nothing to do.

urgency:
  - routine: Comfort, preference, or optimization. No loss of function.
  - soon: Device not functioning, or patient has stopped wearing it. Resolve within days.
  - urgent: Possible medical red flag (sudden hearing change, severe pain, dizziness, discharge or bleeding). Must pair with escalate_medical.

def grouped_bars(table, title, ax):
    """One group per column of `table`, one bar per run (row), colored by run."""
    k, width = len(table), 0.8 / len(table)
    x = range(len(table.columns))
    for i, (run, vals) in enumerate(table.iterrows()):
        ax.bar([xi + (i - (k - 1) / 2) * width for xi in x], vals.values / n, width,
               color=COLORS[run], edgecolor=SURFACE, linewidth=1.5, label=run)
        for xi, v in zip(x, vals.values):
            if v == 0:  # a zero-height bar is invisible, so mark it at the baseline
                ax.text(xi + (i - (k - 1) / 2) * width, 0.01, "0%", ha="center", va="bottom",
                        fontsize=8, color=INK_2)
    ax.set_xticks(list(x), table.columns)
    ax.set_ylim(0, 1.05)
    ax.yaxis.set_major_formatter(lambda v, _: f"{v:.0%}")
    ax.set_title(title)
    ax.legend(loc="upper left", bbox_to_anchor=(1, 1))

Per-example results¶

Each cell is one field of one test row. Correct = matches gold; wrong label = a valid label that doesn't match gold; invented = a value that isn't in the schema at all; no prediction = no parseable JSON, or the JSON lacks that field.

SHORT = {"primary_category": "category", "specific_issue": "issue", "situation": "situation",
         "suggested_action": "action", "urgency": "urgency"}


def cell_state(row, f):
    p = row[f"pred_{f}"]
    if p == row[f"gold_{f}"]:
        return 0  # correct
    if not isinstance(p, str):
        return 3  # no prediction
    return 2 if is_invented(f, p) else 1  # invented / wrong label

STATE_COLORS = ["#256abf", "#c3c2b7", "#d03b3b", "#f0efec"]
STATE_NAMES = ["correct", "wrong label", "invented label (not in schema)", "no prediction"]
STATE_GLYPHS = [("", None), ("", None), ("×", "#ffffff"), ("–", MUTED)]
